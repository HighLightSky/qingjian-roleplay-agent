# 青笺 · 角色与故事

基于 Next.js、assistant-ui 和 IndexedDB 的角色聊天前端。Spring Boot 后端提供聊天、图片能力、模型选图和统一状态整理接口；长期数据保存在浏览器。

## 本地启动

在 `frontend` 目录运行：

```bash
npm ci
cp .env.example .env.local
npm run dev
```

打开 `http://localhost:3000`。默认转发到 `http://127.0.0.1:8080/api/chat`；后端地址不同则在 `.env.local` 设置 `BACKEND_URL`，重启 Next.js。模型密钥配置在原 Spring Boot 后端，前端无需密钥。

也可以使用本机局域网地址访问（例如 `http://172.29.242.179:3000`）。开发配置会将本机 IPv4 地址与 `127.0.0.1` 加入 Next.js 的 `allowedDevOrigins`，保证开发脚本与 HMR 正常启动；通过代理域名访问时，可在 `.env.local` 的 `DEV_ALLOWED_ORIGINS` 中补充主机名，不带协议和端口。修改配置或网络地址后重启开发服务器。局域网 HTTP 下使用 `getRandomValues` 生成 UUID，不依赖仅安全上下文提供的 `randomUUID`。

Next.js 的 `app/api/chat/route.ts` 只进行同源流式转发，直接传递后端的 `context / delta / done / error` 事件，并保留 HTTP 错误状态。部署前端需要 Node.js 服务，不能仅导出静态页面。

## 已实现

- 角色只有名字、身份（与我的关系）、自由角色描述三个文字字段；仅名字必填。支持创建、编辑、复制、归档与切换，已有会话保留创建时的角色快照，新会话为空。
- 一键新建会话，以首条用户消息前 20 个字素簇自动命名；支持手动改名、删除与历史分页。超过 5 个会话时提供标题搜索。
- 复用 assistant-ui 的消息、Composer、滚动、复制、会话列表和操作组件；台词为浅底正文，描写为无背景正文。
- SSE 增量解码与渲染、停止、错误提示、切换会话时取消当前请求并保留已收到内容；同时只运行一个生成任务。
- 每个完整回复后自动检查剧情、记忆和目标，视觉观察合并为一次调用；没有变化则不修改领域数据。顶部“剧情与记忆”集中提供人工修改，支持会话记忆与角色共享记忆。
- 浅绿主题，浅色、深色与跟随系统；手机导航抽屉与全屏记忆面板。
- IndexedDB 事务存储、约 500ms 流式检查点、约 300ms 草稿保存、异常中断恢复；其他标签页只读（浏览器支持 Web Locks 时）。
- 草稿保存在中文输入法组合输入期间暂停，确认文字后再防抖保存；保存状态只更新提示，不触发整个聊天运行时同步，也不向输入框回填草稿。
- 聊天图片上传、本地原图与草稿保存、后续模型选图及可恢复的统一整理任务。
- 完整 JSON 备份 v6（仅接受 v6，不兼容旧版本）、导入预检与事务覆盖、清空确认，以及存储用量与持久存储状态。

选图和统一整理过程使用 assistant-ui Tool UI 展示，可展开查看图片用途、视觉观察、变更前后内容、依据与来源。正文和整理状态独立，整理失败可单独重试；保存失败复用已计算结果，自动模型尝试最多两次。

输入框展示下一次正文请求的上下文占比，草稿变化后防抖 500ms 获取后端预算。纯文本使用部署 tokenizer，有图请求标为保守估算。达到配置窗口的 70% 时，发送前分批压缩较早剧情，保留最近 10 轮原文；原始消息和图片继续保存。每条回复保存并展示正文调用的输入、输出和总 token，不汇总累计消耗。IndexedDB v5 从 v3/v4 保留数据升级，备份 v6 包含摘要、正文用量及可恢复的压缩待办。

模型窗口在后端 `roleplay.context.context-window-tokens` 配置，默认 193024，可通过 `CONTEXT_WINDOW_TOKENS` 覆盖。详情见 [上下文预算与自动压缩](../docs/09-上下文预算与自动压缩.md)。

数据保存在同一站点地址、同一浏览器配置中；改变协议、域名或端口，需要使用备份迁移。关闭浏览器后会恢复已提交的消息、当前角色/会话、主题和输入草稿；正在生成的回复保留最后检查点并标记中断，不自动重发。重新打开默认显示最近消息，原始记录可向上分页读取。清理站点数据或结束隐私模式可能丢失数据，请导出备份。

## 检查

```bash
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

单元测试使用内存 IndexedDB 验证事务、恢复、备份、上下文和 SSE 边界。浏览器测试覆盖桌面和手机，启动测试专用 SSE 服务（18080）和前端（3100），不访问真实模型；测试服务不属于生产后端。

设计依据见 [前端设计](../docs/03-前端设计.md) 和 [记忆、目标与上下文管理优化方案](../docs/04-记忆、目标与上下文管理优化方案.md)。[角色形象照片](../docs/07-角色形象照片与上下文管理.md) 本次仅完成设计，上传功能留待后续。

已有本地服务占用测试端口时，可使用 `ROLEPLAY_E2E_PORT=3101 ROLEPLAY_E2E_BACKEND_PORT=18081 npm run test:e2e` 隔离运行。
