# 整理与挑图：有界材料、短编号与思考策略

本页补充 [后端编排与缓存](./11-后端编排与缓存.md) 的辅助模型输入策略。浏览器请求、SSE 结果、IndexedDB 和备份格式不变；正文与整理仍按现有阶段串行运行。

## 模型材料与真实数据分离

整理与挑图使用显式构造的专用材料，不再序列化完整请求后删除字段。会话、角色和操作 ID，存储版本、指纹、哈希、文件大小、MIME 和交互设置只留在业务快照与校验链路。人工编辑时间与本轮消息时间仍提供给整理器，用于识别新证据。

整理中的记忆、目标、来源消息分别使用 `memN`、`goalN`、`msgN`。映射只存在于单次计算内，裁减和一次纠错共用同一映射。图片继续使用无前导零的 `imgN`，剧情使用已有字段名。输出先按类型严格还原，再执行来源、人工修改和领域校验；不允许猜测未知编号。新增对象仍由后端生成 UUID。

前端只接收真实 ID 和完整变更前后值。模型不再输出版本；后端从冻结快照取得版本，前端继续执行原有提交检查。

本次实际没有原图时，模型可以省略 `visualObservations` 或返回 null，领域结果构造器统一归一为空数组；前端响应始终提供数组。有角色照片或聊天原图时仍必须返回该数组并完整覆盖实际图片。其他三个变更数组始终必需，错误字段类型仍拒绝。

## 默认预算

`roleplay.auxiliary` 集中定义：

| 配置 | 默认值 |
| --- | ---: |
| recent-turns | 4 |
| recent-history-tokens | 8192 |
| current-messages-tokens | 8192 |
| state-input-tokens | 32768 |
| selection-input-tokens | 32768 |
| catalog-entry-tokens | 2048 |
| correction-tokens | 2048 |

旧摘要复用 `roleplay.context.summary-max-tokens`，默认 4096。近期历史按 user 开始划分轮次，不假定严格交替；先保留最近四轮，再按完整轮次缩短。本轮消息独立提供，双方分享预算，长消息保留首尾并标注截断。

总文字预算包含指令、材料包装和纠错；部署窗口还须容纳实际图片估算、输出预留和安全余量。辅助材料优先裁减已结束目标、失效记忆、旧摘要与近期背景，再缩短其他材料。正文原图不替换为文字；无法容纳固定协议和原图属于部署容量错误，仍明确报错。

`incompleteSections`、`incomplete` 标记材料省略或截断。裁减只影响模型投影，不删除历史、不推进摘要游标，不改变消息完成状态。后台中文 WARN 记录任务、阶段、类别、token 或轮次/记录数量，不记录正文全文。

整理材料中的 `editableStoryFields`、目标 `editableFields` 和记忆 `editable` 明确可修改范围；服务端独立检查旧字段确实完整提供。剧情列表继续使用完整替换，列表被省略后不能覆盖。

## 目标与信息价值

目标新增返回完整业务值，更新只提供实际变化的字段；未提供字段原样保留。只修改当前关注点或状态时，不要求重写进展摘要。进展摘要更新必须附 `progressEvidence`，包括类型 `discovery`、`decision`、`outcome` 或 `correction`，来源消息短编号与本轮可见原文引用。历史原文和摘要只能帮助理解，不能成为本轮新证据。服务端验证引用真实存在于本次投影和原消息中；证据具有何种语义仍由模型判断。

整理正式请求和一次纠错均使用 `response_format.type=json_schema` 且 `strict=true`，模板计数保留相同 schema。固定输出四个数组；剧情按字段限制字符串或字符串数组，记忆按完整业务结构返回，目标新增必须完整、更新允许非空字段子集。目标 `value` 只允许 `description`、`status`、`currentFocus`、`progressSummary`，不允许旧字段或存储元数据。每个目标变更的 `progressEvidence` 与 `value` 同级，不需要进展证据时填 null。消息、目标、记忆和图片编号按本次裁减后的实际材料绑定；服务端仍校验引用、写入权限与证据原文。未知目标字段错误列出具体字段名及允许字段，响应中的 Markdown、顶层数组和尾随 JSON 均拒绝并按原规则纠正一次。

整理保留会改变关系、行动条件、目标判断、承诺、关键物品归属及后续因果的信息，包括用户明确赋予意义的称呼和共同经历。寒暄、重复说明与普通行动过程不强行更新。材料未提供不表示旧事实不存在、已解决或失效。

## 选图与思考

挑图仅读取语义背景及精简目录：图片 ID、上传顺序、来源类型和简述、观察、未辨认细节及使用用途。图片目录不重复观察来源，也不包含哈希和存储信息。目录按预算分批，背景最多占选图文字预算的一半。候选阶段不执行最终图片名额限制；合并去重后才统一判断。最终候选过大时精简文字并按明确选中、歧义候选及目录顺序保留，标注不完整。纠错附具体原因和有界的上次结果。

选图提示词的实际图片总上限读取 `VisionProperties.maxImages`，对应 `roleplay.vision.max-images`（当前配置为 10；这是应用数量限制，不是 LLM 固有的图片上限）。最终选图的历史图名额复用服务端计算的 `slots`：总上限减去去重后的本轮附件、首次无观察角色照片等必选资产数。提示词、响应 schema 和结果校验使用同一剩余名额；配置修改并重启后同步生效。候选提取阶段仍不执行最终名额限制，不将候选数误当成实际传图数。

选图正式请求使用 `response_format.type=json_schema`，严格约束顶层对象、四个必需字段、状态枚举、候选图片 ID 和阶段名额。分批、最终选图与纠错都重新绑定本次实际提供的目录；模板计数和剥离图片后的请求保留同一响应 schema。响应必须是唯一完整 JSON，尾随对象同样拒绝，不增加手工剥离 Markdown 或猜测 JSON 的兼容解析。

本轮附件、首次角色照片等必选原图先从可选目录排除，避免重复选择或再次占用历史图名额。没有历史候选时不调用选图模型，本轮必选图片仍交给正文与整理。

模型请求显式携带 `chat_template_kwargs.enable_thinking`：挑图、分批和纠错为 false，正文、整理、整理纠错与历史压缩为 true。正式请求、模板计数及剥离图片后的计数请求使用相同开关；不通过隐藏推理文本声称关闭思考。

本次不新增历史检索或模型阶段，不保证被裁减的早期细节能被重新召回。真实服务组合回归可通过 `mvn -Droleplay.live-llm=true -Dtest=VisualSelectionLiveTest test` 显式启用，部署证书信任使用运行环境配置，默认测试不访问外部服务。

## JSON 响应问题的实测回归

2026-10-23 使用当前 Qwen3.8-27B 部署核查：仅提示词要求 JSON 时曾返回顶层数组；`json_object` 模式在相同样例中也返回数组；明确 JSON Schema 后返回了协议对象。此前反引号开头的异常属于模型输出包装或结构违反协议，不能据此判断角色照片缺失。

真实服务覆盖「无历史、文字历史、图片历史」与「无照片、首次照片、已有观察照片」的九组组合，全部通过。五组存在可选图片时一次返回合法对象，另外四组跳过不必要的选图调用。每组同时验证正确的原图继续进入正文材料。HTTP/SSE 夹具另覆盖同样九组组合的正文与状态整理终态，以及代码块、顶层数组、尾随 JSON 的纠错与原图保留。

整理 schema 的真实部署回归可显式执行 `mvn -Droleplay.live-llm=true -Dtest=StateUpdateLiveTest test`，覆盖新增目标、只改关注点、带原文证据的进展更新；使用 `LLM_BASE_URL` 指定同时提供聊天、`/tokenize` 与 `/apply-template` 的模型服务。
