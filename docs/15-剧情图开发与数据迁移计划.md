# 剧情图开发与数据迁移计划

本计划实现 [视觉上下文方案](14-剧情图生成与视觉上下文方案.md)，外部服务遵循 [生图 API](13-生图服务API.md)。不新增推理工作流、图片数据库或额外视觉 Agent。

## 开发顺序

1. `ImageObservationPolicy.observationAssetIds()` 统一普通整理与手动重试的首次观察集合，保留新上传图正文必选规则。
2. 增加资产出处、Session 视觉状态、sceneImagePlans 和 sceneGenerations；先完成原地升级、备份和回收测试。
3. 扩展现有选图目录，在同次正文调用中流式生成冻结画面计划和中文分层提示词，前端折叠展示；计划无效不破坏正文。
4. `QwenImageClient.edit/cancel`、`SceneImageTaskService.start/subscribe/result/cancel/acknowledge` 接入独立任务，准备真实图片字节；底图和身份图使用原件，辅助图按用途压缩。
5. 前端 coordinator 实现任务恢复、原子保存、重新生成和排除错误图，补齐连续性与迟到结果测试。

每步完成对应测试再进入下一步。后端与前端最终同步发布。张数统一读取现有配置 10；图片生成不占 ModelGate，不阻塞聊天与整理。

## 生成与取消协议

应用 POST `/api/scene-images` 提交 runId、冻结计划、会话角色快照及有序图片引用，返回任务快照。GET `/{runId}/events` 订阅状态，GET `/{runId}/result` 下载 PNG，POST `/{runId}/ack` 在浏览器持久化后释放结果。

后端为每次实际生成分配 UUID，通过 `X-Task-ID` 发送。POST `/{runId}/cancel` 使用相同 Token 和 UUID，在独立连接调用远端 cancel，原生成请求始终继续等待。

| 响应或事件 | 处理 |
| --- | --- |
| cancel 202 | 标记 cancelling；不释放执行名额或原图租约 |
| 原请求 409 TASK_CANCELLED | 标记 cancelled，无图像结果，释放执行资源 |
| cancel 404 TASK_NOT_FOUND | 应用返回 409 GENERATION_CANCEL_NOT_READY，提示稍后手动再试；不自动重试 |
| cancel 超时／失败 | 展示停止请求失败，原生成继续 |
| 原请求完整 PNG 成功 | 成功状态不可被迟到的 cancel 响应覆盖 |
| 重复停止 | 合并正在发送的取消请求，已经接受时直接返回当前快照 |
| 页面关闭／刷新／切换会话 | 只断开前端订阅，后台生成继续 |

重生成使用新 runId 和新 UUID；同 runId 的重连不重复提交生成。后端重启后无任务查询能力，本地标记 unknown，不自动重试。首版一个活跃生成任务，结果保留和字节配额独立配置。

## v8 → v9 原地迁移

`migrateV8ToV9()` 在 IndexedDB 升级事务中新增两个仓库及索引，并补齐以下字段：

- assets.creationOrigin=uploaded，不猜测历史资产实际制作方式。
- Session 及整理／压缩任务嵌套快照的空视觉状态和来源，不增加 stateVersion。
- 旧整理结果 visualChanges=[]，有效 computed 结果继续提交，不重新调用模型。
- 清理旧 dispatch 恢复句柄；尚未完成的正文和运行记录标记中断，保留已收到文本；待整理任务保留并允许手动重试。

角色、快照、原图、哈希、观察版本、消息顺序、图片编号计数器、摘要、草稿与设置均保留。升级事务不执行网络、图片解码或模型调用。失败整体回滚，禁止删库重试。v7 及以下直接阻止升级，保留原库。

新数据库直接创建 v9。多标签页接到 versionchange 后关闭旧连接并停止写入，提示刷新。

## 备份与发布

1. 升级前在旧版本“数据 → 完整备份 → 导出全部”，确认备份已保存。现有 JSON 备份限制为 50 MiB，导出失败应先解决备份问题。
2. 完成或停止聊天与整理任务，关闭其他旧页面，再同步部署前后端。
3. 首次打开执行原地迁移，成功后核对角色、会话、原图和草稿，再导出新版备份。
4. 需要回滚时保留新版数据，在独立浏览器配置中使用旧版本和升级前备份；不降级现有库。

备份导出 v10，导入入口支持 v9 一次性转换，转换规则与数据库迁移共用；运行时只有新协议。包含原件、计划、生成关系和状态，不必保存可重建的派生图。不恢复活动远端任务，导入时在途生成标记 unknown。存在活跃生图时禁止导入／清空数据／删除对应会话，需先结束任务。

## 实现落点与运维参数

- `src/main/java/com/example/service/ImageObservationPolicy.java` 是普通整理与手动重试的共同观察策略；生成图只携带要求摘要，不写入 `visualObservations`。
- `SceneImageStreamParser` 包装原正文解析器，`SceneImagePlanService` 冻结来源检查点、有序参考、原件哈希与生成来源，`SceneImagePromptAssembler` 校验八段中文提示词及编号。计划指纹对目标字段排序，跨后端重启保持一致。
- `SceneImageController` 与 `SceneImageTaskService` 提供创建、快照、SSE、PNG、停止与 ACK。`PUT /api/scene-images/inputs/{sha256}` 把按用途准备的真实文件放入原 `ImageCache`；`QwenImageClient` 复用项目 HttpClient 和 Spring multipart 编码器，通过独立 HTTP/1.1 请求取消。
- `frontend/lib/images/model-input.ts` 保留底图和身份原件，辅助参考默认最长边 1024、JPEG 质量 0.85，PNG 保留透明通道；粗略环境／姿势可复用已有缩略图。派生哈希与原件哈希分别记录，浏览器弱引用缓存可复用相同派生版本。
- `frontend/lib/scene-images/coordinator.ts` 的 `startSceneGeneration()`、`followSceneGeneration()`、`saveGeneratedImage()`、`stopSceneGeneration()`、`resumeSceneGenerations()` 负责生命周期；图片卡片独立订阅并支持“此图有误”。生成结果永不更新正文检查点或当前视觉状态。
- `frontend/lib/scene-images/migration.ts` 定义唯一旧字段转换规则，供 `migrateV8ToV9()` 和 v9 备份转换共同使用。计划和生成关系纳入完整备份、图库和引用回收。

`roleplay.vision.max-images=10` 是数量配置唯一来源；`roleplay.image-generation` 集中配置外部资源限制。生成读取超时 1800 秒、任务总截止 1900 秒、停止请求超时 10 秒；用户取消不会触碰系统截止时间或原连接。结果默认保留 7200 秒，最多 4 个结果槽位，每槽预留完整 64 MiB PNG 及元信息；额度耗尽明确拒绝新任务。

后端设置 `IMAGE_SERVICE_BASE_URL`、`IMAGE_SERVICE_API_TOKEN` 并信任服务 TLS 证书。未设置 Token 时聊天正常，点击生图给出未配置原因；前端不会取得 Token。部署步骤见 [DEPLOY.md](../DEPLOY.md)。
