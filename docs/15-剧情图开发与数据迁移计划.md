## v8 / v9 → v10 数据库

浏览器数据库仍名为 roleplay-agent。新数据库直接建立 v10。v8 沿用原有视觉状态与出处字段升级，并建立生图仓库；v9 在单个版本升级事务内转换所有业务记录。

- 保留角色、会话、正文、原件 Blob、哈希、消息次序、观察版本、摘要与草稿。
- 画面草稿移除 action/status、前幕、连续性、场景编号、八项目标、摘要和指纹，保留原始提示词及参考建议。编辑草稿首次打开时读取能力接口默认尺寸，不复制前端常量。
- 旧生成记录从原计划复制实际发送的提示词；成功结果尺寸取资产元数据。旧协议未记录的派生输入哈希、未知任务请求尺寸使用 null 明确表示未知，不假装它们等于原件或默认尺寸。
- 移除所有嵌套 scene_generation 来源中的旧场景编号及目标字段。旧 base 用途移除，其参照范围文字保留。
- 在途生成标记 unknown 并保留内容，不自动重放。旧聊天恢复句柄清理，保留中断正文和可恢复整理材料。
- 迁移失败整体回滚，原库仍可用；不删库重建。v7 及更早版本继续阻止自动升级。

数据库升级不执行模型调用、图片解码或网络请求。其他标签页收到 versionchange 后关闭连接，停止旧版本写入并提示刷新。

## v9 / v10 → v11 备份

导出统一 v11。v9 先通过既有入口转换，再与 v10 共用本版记录迁移。转换后只按新协议校验，运行时不保留旧 DTO 或行为分支。

备份保留实际原件、草稿、生成提交快照和引用，不必保存可重建派生文件。导入不恢复远端活动任务；成功图片、失败与放弃记录可恢复。存在活跃生成时仍禁止导入、清空及删除对应会话。

## 发布与回滚

1. 在当前旧版导出完整备份并确认保存成功；备份现有 50 MiB 限制不变。
2. 结束活动任务，关闭其他旧标签页，同步部署前后端。
3. 打开新版执行原地升级，核对角色、会话、原件、草稿、历史生成图和放弃记录，再导出 v11 备份。
4. 回滚时保留新库，在独立浏览器配置中用旧版本及升级前备份；不得用旧前端打开 v10 库或降级原库。

## 配置与生命周期

`roleplay.vision.max-images` 仍为数量唯一来源。生图能力中的 maxReferenceImages 由它减去一张黑图计算。

`roleplay.image-generation` 新增 default-width=256、default-height=512、dimension-alignment=32；前端通过能力接口读取。原有单图、请求、像素、输出、参考压缩、独立超时与缓存额度配置继续生效。

远端地址和 Token 仅在后端使用，需正确配置 JVM TLS 信任；不关闭证书校验。生成原连接和独立取消连接的行为不变：202 后等待原请求的成功或 TASK_CANCELLED，不提前释放名额。结果保留两小时；ACK 后释放结果。

## 自动化与人工验收

自动化使用 HTTP 夹具，不访问 GPU。覆盖真实 multipart 中文、纯黑首图与尺寸、空参考、编号自由文本、资源边界、幂等重连、取消竞争、编辑确认、草稿刷新、提交快照、放弃重生成、实际提示词目录、备份及数据库回滚。

执行 `mvn test`、前端 `npm test`、`npm run typecheck`、`npm run build` 和相关桌面/手机 Playwright 用例。真实服务的黑图重绘效果、实际输出画幅、人物连续性及停止生成另行人工验收；HTTP 夹具成功不代表画面效果验收通过。

本次自动化结果：`mvn clean test` 共 168 项，166 通过、2 项真实模型测试跳过；前端单元/集成测试 85 项通过，类型检查通过。桌面与手机浏览器 22 项相关用例通过，包含 v8/v9 原生 IndexedDB 升级、备份恢复、附件与角色照片回归，以及生图编辑、刷新、取消、放弃和重生成。生产构建通过。真实 GPU 服务的画面效果与实际输出尺寸尚未人工验收。
