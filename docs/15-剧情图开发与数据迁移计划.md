## 版本与迁移

IndexedDB 当前 v14，完整备份当前 v16。动作库范围通过 v13→v14 数据库和 v15→v16 备份迁移为既有草稿（含 computed 计划）补 poseLibrary=default，保留候选、选择和姿态编辑，不改历史提交快照。姿态编辑的 v12→v13 数据库和 v14→v15 备份迁移见 [16](16-前端姿态编辑与渲染.md)，以下旧迁移在链中保留。数据库名保持 roleplay-agent，保留已有 v8—v10 升级链后再执行 v11→v12；旧 v11 直接进入本次迁移，不能再次执行会清除 computed 计划的更早迁移。备份 v9—v13 在导入入口依次迁移至 v14。

迁移覆盖 sceneImagePlans、sceneGenerations.submission 和 operations 中 state_update.result.scenePlan。旧计划的 poseQuery、characterReferenceAssetId 为 null；已有编辑草稿的姿势关闭、检索描述为空、候选为空。旧提交快照的姿势关闭、选中姿势为空；保留用户提示词、effectivePrompt、尺寸、参考顺序和图片原件，不从旧提示词猜测动作。失败迁移须原子回滚。

新数据保存全部候选与状态至草稿，每次生成快照只保存选中的完整 pose。备份 v14 校验候选结构、引用与选中项；资源统计自动计入完整 JSON 字节，完整姿势不进入模型上下文。已有参考资产回收规则和备份的原件完整性约束继续生效。

## 配置与发布

1. 在旧版导出完整备份，等待当前聊天和生图结束，关闭其他旧标签页。
2. 升级外部生图服务至 bd915865 或更新版本，核实姿势索引、embedding、渲染依赖、取消路由及 library 检索范围支持。若服务尚未载入新增动作库范围，执行 `sudo systemctl restart qwen-image-api.service`。版本需部署人员核验，接口无版本查询。
3. Spring Boot 设置 API_BASE_URL 和 IMAGE_SERVICE_API_TOKEN，同步发布前后端；不要让旧前端打开 v14 数据库。Token 未配置时保留聊天能力，关闭生图能力。
4. 默认就绪超时 10 秒、检索超时 60 秒、单 pose 1 MiB、检索响应 4 MiB、检索请求 64 KiB、top_k=3；均在 roleplay.image-generation 定义。原生成 1800 秒超时、取消独立连接、结果保留两小时不变。
5. 核对历史原件、编辑草稿、生成快照及新检索选择，再导出 v16 备份。回滚使用独立浏览器配置与升级前备份，不能降级原库。

/ready 只检查图像服务，无法证明姿势索引或 embedding 可用。未就绪或姿势错误必须呈现具体错误，不自动退回普通生成，不自动重新提交随机生图任务。

## 自动化与人工验收

自动化使用 HTTP 夹具，不连接 GPU。覆盖结构化双文本与一次纠错、鉴权和 ready 顺序、多候选及完整 v3 字段、查询过期响应隔离、刷新恢复、失败手动重试、关闭姿势合并动作、人物图排序、multipart 文本 pose 与资源限制，以及取消和错误 PNG 防护。

数据测试覆盖 v11 原地升级失败回滚、computed 内嵌计划、历史备份导入及 v14 姿势备份往返；桌面与手机测试覆盖自动检索无需展开、候选选择与人物图切换、刷新保留、无候选和普通模式切换。

执行 mvn test；前端执行 npm test、npm run typecheck、npm run build，以及相关 Playwright 用例。

真实服务另行人工生成站立、拳击、坐姿、跳跃，验证画幅图＋多张参考图＋pose 的尺寸、外观、左右肢体、支撑关系和观察角度，再测试指定任务取消。HTTP 返回成功不能替代画面效果验收；发现偏差时由用户重新检索、换选候选或修改提示词。
