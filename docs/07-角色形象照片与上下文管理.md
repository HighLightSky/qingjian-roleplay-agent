# 07｜角色形象照片与上下文管理

> 2026-10-21。本文件是后续实现设计，照片上传、照片绑定和照片选图尚未实现。本次已完成的是角色三字段改造：名字、身份（与我的关系）、自由角色描述。新会话为空，由用户发送第一句；不提供旧数据兼容。

## 1. 形象照片的作用与编辑体验

角色编辑页保留三个文字字段，另设可选的“形象照片”区域，允许选择一张静态 JPEG/PNG，显示预览，并支持替换、移除。照片主要帮助模型维持外观连续性，例如发型、衣着、轮廓和配饰；不从外貌推断性格、职业、身份或与用户的关系。

复用现有图片准备、尺寸/体积校验、缩略图与 assets Blob 存储。限制以现有能力接口为准，不另设一套图片上限。原图长期在浏览器保存，后端仅在请求中接收字节，不增加服务端图片存储。Object URL 按展示生命周期创建与释放。

上传完成仅表示本地保存，界面不能显示“模型已记住”。保存角色不发起模型调用，也不将识别结果自动填入或改写自由角色描述。视觉能力不可用时，已有照片仍可查看和移除，新照片准备及依赖照片的生成明确报错。

## 2. 版本、快照与资产生命周期

后续在角色资料及会话角色快照上增加可选的 `appearancePhotoAssetId`，无照片时省略；三个文字字段保持不变。复用现有 `profileVersion`：保存照片替换或移除与文字修改一样增加版本，新会话复制当时的文字、版本与照片引用。

- 编辑当前角色不影响旧会话；旧会话不会查询当前角色照片来覆盖自己的快照。
- 复制角色时可复用相同资产，但创建独立角色及引用，不复制会话、观察或共享记忆。
- 每个会话首次使用其快照照片都独立建立观察。同一文件 SHA-256 去重仅减少存储，不扩大跨会话观察与故事信息的共享范围。
- 删除会话、替换照片或移除角色草稿后，先检查角色、全部会话快照、角色草稿、聊天消息、附件草稿、观察、使用记录及待处理任务的引用，再清理未引用资产。
- 照片准备过程中使用临时引用保护资产；保存或取消草稿时在事务中交接或释放引用，防止并行图片清理删除未保存照片。

## 3. 首次看图与后续模型选图

复用 `/api/context/inspect`、`/api/chat` 和 `/api/visual/update`，扩展来源协议，不另建照片专用聊天流程。

### 首次使用

会话尚无已提交的照片观察时，将快照照片列为必需原图，正文模型实际接收它；不先生成 caption 再用文字替代图片。模型输入单独标明“角色形象参考，来源于角色资料版本”，不插入虚假的用户上传消息，也不表示故事中有人递出了一张照片。

正文成功完成后，登记可恢复的视觉整理任务，整理模型实际接收原图，建立可见外观事实、可辨文字和不确定项。失败保留正文及待处理任务；重开页面或下一次生成前重试。取消、异常结束或未提交的观察不能解除首次参考要求。

### 后续轮次

1. 每次准备上下文，从会话快照取照片，加入独立的角色照片目录项；普通聊天图片目录继续按现有规则构建。
2. 将已确认的外观观察、来源与当前剧情状态一起提供给选图模型。即使会话没有任何用户图片，角色照片也能触发选图。
3. 选图模型根据本轮语义选择零张或多张原图。已有观察足够时可不重读；追问面部、饰品、小字或其他未记录细节、核对冲突和图片比较时应重读。业务代码不使用关键词或固定轮数判断相关性。
4. 照片被选中后，从本地读取原图，并与本轮新图及选中的历史图合并，按 assetId 去重后发送。未被选择时仍保留外观观察，但不声称本轮重新核实了原图细节。

首次必需图、聊天新图和按需选中的图共用图片数量、像素、单图与请求体限制。首次照片占用一个不同资产名额；与本轮附件为同一资产时只计一次。名额不足或必需字节丢失时明确停止，不偷偷遗漏角色照片。

## 4. 来源协议与校验边界

当前图片来源只接受消息位置，观察强制要求消息 ID，因此不能直接将照片塞进旧目录并伪造消息。后续将来源扩为有判别字段的联合类型：

```ts
type VisualSource =
  | {
      type: "message";
      messageId: string;
      seq: number;
      text: string;
      imageIndex: number;
      uploadIndex: number;
    }
  | {
      type: "character_photo";
      characterId: string;
      profileVersion: number;
    };
```

目录按资产合并并保留全部用途来源，角色照片不占用“第几张聊天上传图”的编号。观察也保存真实来源；首次照片观察可没有上传消息 ID，实际使用它生成的回复记录在使用记录里。

选图指纹包括三字段快照、照片资产 ID、角色快照版本、图片哈希、观察版本、文字历史和剧情材料，继续排除计划自身及字节载荷。前后端基于同一份发送快照工作，旧计划和迟到任务不能覆盖不同版本的数据。

服务端入口校验角色照片引用确实匹配请求快照、目录来源和所传元信息，限制可选 ID 为当前会话目录及其角色快照照片；实际字节继续检查真实格式、解码尺寸和哈希。无状态服务不声称能独立认证客户端数据库所有权，会话隔离由浏览器读取和请求引用一致性共同保证。

观察、使用记录、视觉任务、备份校验及图库来源展示同步适配联合来源，不留下只接受用户图片消息的旧校验路径。此扩展实施时直接升级协议与备份格式，不要求当前 v3 能读取未来数据。

## 5. 外观观察、剧情状态与压缩

生成提示词明确区分三类依据：

| 依据 | 用途 |
| --- | --- |
| 角色文字设定 | 身份、关系及用户明确赋予的设定；与照片不同的明确文字设定优先用于故事 |
| 照片原图与外观观察 | 记录图中实际可见的形象；模糊细节保持不确定 |
| 当前剧情状态 | 换装、受伤、光照等已经发生的变化，决定此刻如何描写角色 |

例如照片是红色斗篷，用户后来写“她换上白裙”，当前服装可以是白裙，照片观察仍记录红斗篷。文字设定为银发而原图为黑发时，故事遵循银发设定；观察仍保留原图黑发，不修改图像事实，也不把冲突当作剧情中已经发生的染发事件。

当前阶段复用视觉观察，将稳定外观事实与不确定项作为独立的角色参考材料注入上下文，不写入用户手动维护的记忆表。对话原文被手工整理或移出最近 20 条历史后，照片目录和观察仍由快照引用直接加载，不依赖旧消息是否保留在模型输入中。

未来自动记忆与上下文压缩接入后：

- 稳定外观观察归于角色参考层；当前服装等变化归于剧情状态层。压缩不将原图事实与剧情变化混成一条永久设定。
- 压缩保留 assetId、角色快照版本、观察版本及未识别细节，允许从本地原图重新读取。
- 新观察替换旧观察，保留版本关系；引用旧观察的派生记忆和上下文预览随之失效。
- 图片输入计入实际模型预算；未重读时只计算文字观察，不把保存了一张图宣传成每轮看图。原图或未压缩资产引用不因摘要而清除。

## 6. 错误、备份与验收

照片原件缺失、损坏、哈希不符，或当前模型不支持视觉时，明确说明原因并停止相关生成；不换成文字占位。模型明确选中的照片超限时同样停止。已有正文保留，视觉整理失败通过持久任务重试，不回填虚假的成功观察。

备份包含角色照片引用、旧会话照片引用、角色草稿、原始字节、带来源的观察及待处理任务。每个资产只导出一份原件，导入先检查全部引用、版本、哈希及体积，再原子替换。不能只导出预览图，也不能在超限时省略照片。

后续实施至少验收：

1. 创建角色上传一张图，首次正文确实带原图，整理失败可恢复，角色描述原文不变。
2. 纯文字后续轮次仍会选图；选择零图时使用已有观察，细节追问选择照片后实际重读原图。
3. 换装后遵循剧情状态，照片观察不被故事改写；明确文字设定与照片冲突时保持上述分工。
4. 替换或移除照片只影响新会话；旧会话刷新、切换及导入备份后仍能读取原照片。
5. 同图在角色资料与消息中使用时只传一次，来源用途都保留；照片不改变聊天图片上传编号。
6. 其他角色和会话的私有聊天图片不进入当前目录，照片观察不因资产去重而跨会话共享。
7. 删除会话不删除仍被角色、快照、草稿或任务引用的图；所有引用释放后可清理。
8. 缺图、能力关闭、数量/字节超限均可定位，生成不静默降级；摘要之后仍可选图和追问细节。
