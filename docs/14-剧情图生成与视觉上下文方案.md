# 14｜剧情图生成与视觉上下文方案

2026-10-29 修订。外部协议以 [API.md](API.md) 为准，部署与升级见 [15-开发与数据迁移](15-剧情图开发与数据迁移计划.md)。

## 整理与草稿

正文完成后，现有一次严格 JSON Schema 整理调用同时返回领域变更和画面草稿，不自动生图：

```json
{"sceneImage":{"poseQuery":"坐姿，双脚落地，左手扶书，右手搭在书页上，头部低垂。相机从侧面观察。","prompt":"与<image2>相同的人物，身上穿白衬衫，外套搭在椅背。书桌上有一本书，窗边日光。","additionalReferences":[]}}
```

poseQuery 只生成精简的动作描述：先概括整体姿势或动作，再描述有辨识度的躯干倾斜、四肢位置、头部方向和身体接触关系，不逐项凑齐。人物左右以人物自身为准，无法确认时省略左右，不猜测。允许常见动作名称，但不推测静态图片无法证明的运动过程、动作意图或故事经过。

人物身体朝向与相机观察视角分开描述；相机视角只在有依据且有助于检索时写入。局部特写只写可见部位，不补全画面外或被遮挡的肢体。接触关系必须有依据，不臆测图片中不存在或材料未说明的座椅、道具、支撑物与接触；必要接触物只使用通用名称。

poseQuery 不描述人物身份、姓名、年龄、性别、容貌、服装、画风、背景、情绪或故事，不夹带地点、时间、光线、物品外观或图片引用。只有站立依据时只写“站姿”，不以“位于书桌旁”等背景补足篇幅；头部方向使用姿态词，不写“望向窗外”等场景目标。prompt 承载人物参考、服装、必要物品、场景、光照和需要保留的特征，不重复身体动作。例如酒店门口提纸袋的画面，检索描述只保留站姿、身体微侧、手臂位置、握提手与偏头，不写酒店、台阶或纸袋材质。

两者都必填，在模型输出边界校验，沿用一次纠错。当前服装与身份照片不同时仍需补选对应服装参考；生成要求不作为剧情事实或原图观察。

后端返回的 scenePlan 增加 poseQuery 和 characterReferenceAssetId。会话角色快照照片自动作为默认人物参考；无照片时不猜测人物来源，由用户指定。参考依旧只从本次有界目录选择，未知编号、重复引用、空用途和超额在模型输出边界拒绝。

浏览器在同一事务中提交领域变化和草稿；重复取回整理结果不覆盖编辑内容。默认宽高 512×512，按能力接口中的 32 像素单位向上对齐；新回复使用默认值，同一回复持久化草稿。

## 姿势检索与编辑

新草稿默认开启“使用姿势参考”。写入 IndexedDB 后由协调器自动调用应用接口 `POST /api/scene-images/poses/search`，正文与整理不等待检索，卡片无需展开。请求为 `{"query":"动作描述"}`；后端先调用 `/ready`，再以配置的 top_k=3 调用远端 `/api/pose/search`。

应用返回 `matches`，每项为 `poseId`、`score`、`description.zh/en` 和完整 `pose`。保留所有角色、骨骼、相机和缩放字段，不裁剪、不修改。score 仅展示为相似度，不当作概率，不使用固定拒绝阈值，不默认选中首项。

用户可改描述、重新检索、切换候选，并通过“编辑姿势”在本地人体视口调整骨骼、人物位置和输出构图，详见 [16-前端姿态编辑](16-前端姿态编辑与渲染.md)。只保留当前候选的已应用编辑，切换候选会清空。修改描述立即清空候选与选择；每次请求递增版本并绑定查询，迟到响应不能覆盖较新内容。重新检索也清空选择。关闭姿势参考保留草稿里的候选、选择和已应用编辑；开启后仍须满足当前查询已成功检索并手动选中候选。

检索状态、查询、版本、完整候选、选择和错误持久化。刷新不重复检索已成功或失败的结果，只恢复中断的检索。只有持写锁的标签页自动检索，恢复时串行发送，避免集中占用检索名额。错误在姿势区域呈现；不会失败整个整理，也不会自动改成普通生图。

姿势模式必须从已选参考中明确指定人物图。默认角色快照照片可更换；取消勾选当前人物图后清空人物选择并提示重新指定，不把其他图自动当成人物图。

## 提交、图片编号和提示词

`POST /api/scene-images` 保留 runId、source、prompt、width、height、referenceImages，新增 poseEnabled、poseQuery、characterReferenceAssetId、poseSelection。poseSelection 为完整候选对象；姿势关闭时为 null。服务端只在入口校验请求，要求姿势模式具备有效候选、查询和 image2 人物图，校验 pose 对象类型与体积，内部骨骼语义交给远端服务。

前端统一计算展示及上传顺序：image1 为后端生成的黑色画幅图；姿势模式将指定人物参考排到 image2，其余参考保持相对顺序。所有参考仍按原图、剩余像素预算、referenceMaxEdge/referenceJpegQuality 压缩；原件不变。首图占一个图片名额，最多九张参考。更换人物参考后展示新编号，不自动改写用户提示词中的自由文本引用。

姿势模式的程序说明为 image1 用于人偶姿态、image2 用于人物身份和外观，其后列出参考用途，再附用户 prompt；不再出现旧黑画布说明，也不重复远端自动添加的 `Draw character from image2`。远端收到重复的 images 文件字段、prompt 文本和完整 pose 序列化文本，multipart boundary 由标准表单转换器生成。

普通模式沿用黑画布说明，将 poseQuery 作为姿态要求追加到用户 prompt，不传 pose。旧草稿 poseQuery 为空时保留原有文本行为。资源库 `/direct` 仍走原始图片及提示词普通编辑，不增加姿势功能。

提示词编辑确认继续保留，只改尺寸或姿势选择不额外弹窗。每次生成使用新 runId 和新的远端 UUID，冻结用户文本、实际发送的 effectivePrompt、尺寸、图片顺序、人物参考、姿态查询和本次最终完整 pose（优先使用已应用编辑）。JSON 姿势按内容比较，不受对象字段顺序影响；修改草稿不修改已提交任务。

## 任务和后续视觉上下文

沿用现有独立活跃生成任务、快照、SSE、result、cancel、ack 和 inputs 接口，不占用聊天 ModelGate。生成前也先检查 `/ready`；就绪检查不代表姿势索引或 embedding 可用，不提供远端进度百分比。

成功必须为 HTTP 200、image/png，并通过体积、像素、解码和完整 IEND 校验，之后才入浏览器资产库；JSON 错误、错误类型或截断结果不能保存为图片。取消使用独立 HTTP 连接和同一任务 UUID，202 后等待原请求结束才释放名额。网络超时/断开只标记结果未知，不自动重新生成；页面关闭仅断订阅，结果取回和 ACK 可重试。

生成结果可再次生成或放弃。放弃保留记录、排除后续来源，并原子回收没有其他有效引用的原图。生成不推进剧情检查点，不直接修改视觉状态。

后续上下文只使用实际 effectivePrompt，并标记未经图像核实；完整 pose、候选和检索状态不进入聊天或整理材料。完整备份包含姿势草稿和提交快照，容量统计按实际 JSON 字节计入所属会话；画幅图不注册资产、不分配 imgN、不计入图库或后续参考。
