# 14｜剧情图生成与视觉上下文方案

2026-10-25 修订。每次生图独立提交，固定以黑色画布指定画幅，人物照片和历史图片只作参考。外部服务协议见 [13-生图服务 API](13-生图服务API.md)，升级与发布见 [15-开发与数据迁移](15-剧情图开发与数据迁移计划.md)。

## 1. 产品行为

- 普通聊天不自动调用生图服务。正文正常完成后保存独立画面草稿，不等待图片生成才整理状态。
- 用户可修改提示词、宽高和参考清单。默认宽 256、高 512；新回复恢复默认，同一回复保留编辑草稿，刷新可恢复。
- 尺寸按服务的 32 像素规则向上对齐，提交前显示实际画幅。默认值、对齐单位和限制读取 `/api/capabilities.imageGeneration`。
- 提示词与原始模型建议不同时，提交前弹窗：**修改提示词可能导致视觉上下文不连贯，是否要继续？** 选择“返回修改”不创建任务、不发送生图请求；选择“继续生成”提交。只改尺寸不弹窗。
- 每次生成使用新 runId，冻结用户提示词、最终实际提示词、画幅和传输参考。修改草稿不修改已发请求，取回结果不再读取当前草稿。
- 成功后可“放弃这张”或“再次生成”。放弃保留图片与记录，标记 rejected，排除后续生成来源；编辑草稿不清空。普通再次生成不自动放弃旧图。
- 前轮没有点击生成、生成失败、放弃结果，都不影响后轮生成。生成结果不推进回复检查点，不直接修改剧情或当前视觉状态。

## 2. 底图与参考

后端为每次请求创建不透明纯黑 PNG，固定放在 multipart 第一个 `images` 字段。黑图只指定画幅，程序说明要求重绘完整画面，黑色不代表目标背景或风格。

黑图不注册浏览器资产、不分配 imgN、不保存到图库、不作为下一轮参考。它计入输入张数、像素和请求体预算：十张输入上限下最多九张参考，聊天图片上限仍为十张。

参考图按以下规则准备：

1. 当前会话有可用的角色快照照片时程序自动加入，优先承担人物身份用途。没有照片也允许生成。
2. 模型可建议有效历史生成图作身份参考；这是提示词指导，后端不检查“必须有身份图”。
3. 其他图片只按本次需要选择，历史生成图不是必须编辑的前幕。
4. 按资产编号合并重复项及用途；角色照片优先，其他 identity 参考其次，其余保持首次出现顺序。
5. 用户可取消勾选参考。已放弃的生成来源、缺失原件和无效引用显示具体编号，允许移除后重试，不静默删除已选参考。

所有参考，包括人物身份参考，都允许压缩。原件保持不变，派生输入具有自己的 sha256，并记录 sourceSha256。使用剩余像素预算和现有 referenceMaxEdge/referenceJpegQuality 准备输入，服装或身份参考不使用粗略缩略图策略。

角色照片来源始终使用当前会话快照，不受后来修改角色资料影响。生成图只有成功、未放弃且关联回复检查点有效时进入候选；同一原件仍可保留其他真实上传来源。

## 3. 主模型尾部协议

正文结束后必须另起一行输出 `[生图提示词]`；需要额外参考时可在它之前附 `[画面计划]` JSON：

```text
[画面计划]{"referenceImages":[{"assetId":"img1","roles":["identity"],"scope":"只参考人物面部与发型"}]}
[生图提示词]
[主体]李白穿白色宽袖长袍，扶松树侧身回望，面带微笑。
[环境]瀑布旁的山道，水雾弥漫，脚下是湿润青石。
[光线]白天柔和自然光，水雾散射光线。
[材质]棉麻白袍，粗糙松树皮，湿润青石。
[构图]中景侧面构图，人物居左，右侧露出瀑布。
[风格]中国水墨淡彩，背景适度留白。
```

JSON 只表达资产、用途和参照范围，不要求单行；没有额外参考时可以省略 JSON，角色照片仍由程序自动注入。允许用途为 identity、continuity、outfit、environment、pose、prop；continuity 只表示参考用途，不带前幕依赖。

系统提示要求模型每轮正文正常完成后，在同次输出中用 `[生图提示词]` 分隔，并按 `[主体]`、`[环境]`、`[光线]`、`[材质]`、`[构图]`、`[风格]` 六段依次生成，附简短完整示例引导格式。没有用户生图请求、没有额外参考或剧情变化很小时，也不省略尾部；正文篇幅要求不包含生图提示词。

六段结构是自动生成的写作要求，不作为用户编辑后提交的校验门槛，不要求独立摘要。程序不检查提示词是否含 `<imageN>`、是否覆盖所有参考，不推断或改写自由文本里的 imgN。

模型不再填写 action、previousPlanId、场景连续性类型、八项目标和计划指纹。参考 JSON 使用 Jackson 确定边界，随后接收自由提示词；没有参考 JSON 不属于解析错误。解析错误保留草稿与具体诊断，用户仍可直接编辑生成；不可用的参考保留可移除项，不把提示词永久锁为不可生成。

本轮附件的原件元信息与真实上传来源也进入目录，但不参加历史候选选择，仍由系统必选。整理器直接复用已存在的本轮上传来源，避免重复登记或推进上传编号。

本会话目录在现有辅助上下文预算内投影，优先提供近期图片，裁减时明确标注不完整。可以建议本轮没有重读的图片，但不能声称已核实细节。人物身份连续性主要由提示词和有效参考表达，不以数据库前幕链作为生图门槛。

## 4. 应用接口与校验

`POST /api/scene-images` 接收：

```json
{
  "runId": "本次任务 ID",
  "source": {"planId":"草稿 ID","sessionId":"会话 ID","assistantMessageId":"回复 ID","sourceSeq":2,"sourceCheckpointVersion":1},
  "prompt": "用户本次填写的提示词",
  "width": 256,
  "height": 512,
  "referenceImages": [{"assetId":"img1","roles":["identity"],"scope":"面部","sha256":"传输版本哈希","sourceSha256":"原件哈希","sourceGenerationId":null}]
}
```

前端按最终清单补齐派生文件缓存。后端在一次入口校验中检查来源结构、非空提示词、尺寸、参考数量和哈希结构，随后创建黑图、检查实际文件资源并调用外部服务。最终提示词由黑图说明、实际参考顺序说明和用户文本组成，长度上限包含程序追加文字。

任务快照增加 submission：用户文本 prompt、实际发送的 effectivePrompt、对齐后宽高及实际 referenceImages。重连仍能取得同一提交快照。相同 runId 按请求记录的值相等比较，避免序列化字段顺序影响幂等性。

继续使用 GET 快照/SSE/result、POST cancel/ack 及 PUT inputs；一个独立活跃生成任务，不占聊天 ModelGate。关闭页面只断开订阅，不取消后台任务。结果持久化成功后 ACK；ACK 或结果取回失败可重试，不重复生图。

保留服务端资源信任边界：图片格式、单图体积与像素、总像素、multipart 总字节、提示词长度、PNG 完整性与输出限制。底图生成前先校验尺寸，防止未受限分配像素内存。校验不要求人物照片、前幕、固定中文格式或图片编号覆盖。

## 5. 后续视觉上下文

生成记录持有独立 submission。目录和图库显示该次实际发送的 effectivePrompt，不读取后来修改的草稿，也不使用原模型摘要或八项目标。生成要求始终标注未经图像核实，并按现有上下文预算裁减；不额外调用摘要或看图模型。

用户放弃某次结果后，只排除该次生成来源，不删除共享资产或其他有效来源。后续整理只根据对话证据更新视觉状态，不能把生图要求自动写成剧情事实。

完整备份包含草稿、每次提交快照、图片及其引用。计量与引用回收同时遍历草稿参考和生成快照参考；黑图不参与资产计量。
