# 16｜前端姿态编辑与渲染

2026-10-30。当前项目实现浏览器本地人体编辑；不修改外部 Python 生图服务。生成协议仍见 [API.md](API.md)，剧情图流程见 [14](14-剧情图生成与视觉上下文方案.md)。

## 固定资源与装配

复用 AHEKOT/ComfyUI_VNCCS_Utils 提交 `334eee549fba5025b97c4e0a6123b2b68a46f0fc` 的 PoseViewerCore、MakeHuman 体型模型、morph Worker、场景及相机辅助函数、本地 Three.js 和贴图。依赖及 SHA-256、体积清单集中在 frontend/scripts/pose-assets.json，MIT 和 CC0 许可一同部署。

npm run dev/build 的前置脚本准备资源；也可手动运行 npm run prepare:pose。首次准备需要访问固定源码地址，之后校验本地缓存，无需重新下载。资源位于忽略 Git 的 public/vendor/vnccs/固定版本目录，运行时只访问本站；部署必须包含生成后的 public 目录。缺失或校验失败会明确中止准备，不替换资源版本。

小型自有场景适配器 public/pose-editor/runtime.mjs 负责模型消息转换、身体比例、全部人物装配、输出相机与截图；不导入 ComfyUI 完整 Widget。模型计算在独立 Worker 中完成，相同体型在一个编辑会话内复用。其他人物分别装配后克隆为不可编辑人物，不能直接共用当前人物的体型。切换编辑人物不修改 JSON 的 active_character_id，输出相机锚点始终来自原活动人物。

弹窗打开才加载代码、模型和 WebGL。关闭时销毁 Worker、所有绑定的 canvas 事件、控件、几何、材质、贴图、ResizeObserver 和预览 Blob URL。原资源包约 36 MiB，首次加载速度取决于网络与浏览器；普通聊天不加载该资源。

## 编辑与输出

姿势 JSON 只校验传输格式和基本结构：顶层必须是对象，存在 bones、characters、poses、image_poses 中任意一个字段即可；不要求字段值满足内部 Schema，不要求相机、材质、体型、骨骼齐全，不校验姿势质量。不限制版本、骨骼名称、角色数、姿势数或人体参数范围，不删除未知字段。序列化检查所有字段中的非有限数值，禁止 NaN、Infinity、-Infinity 被静默转换成 null；非法 JSON 明确报错。最终 JSON 文本按 UTF-8 字节数与服务端 poseMaxBytes 比较，默认配置为 1 MiB，不截断数据。检索、编辑保存、备份恢复及生图提交共用这套基础规则。

本地视口用独立副本解释顶层骨骼单姿势、poses/image_poses 单人场景及 characters 人物场景。渲染所需的缺省值只存在于视口副本，不改写原版本或补进提交数据。打开、恢复或切换人物不修改原始 JSON；应用时只将用户实际改动的骨骼、人物变换和机位字段合并回原包装，保留其他人物、姿态和未知字段。mesh 体型由固定版本上游模块解释，第一版不提供体型编辑、动画时间线、增删人物或 JSON 文本编辑。

界面支持关节 IK 拖动、骨骼旋转、人物 X/Y/Z 与缩放、输出机位偏移/缩放/水平角/俯仰角、多角色切换、撤销重做、恢复检索姿势。观察用 Orbit 相机不写入 JSON，只有构图控件更新输出相机；骨骼编辑仅合并 bones、bonePositions、modelRotation、IK、pole 与 hip 状态，保留原有未知字段和其他姿态。

生成预览使用 PoseViewerCore.capture() 的固定输出相机和当前实际画幅，白底、naked 材质、白色环境光强度 1，关闭方向光穹顶并隐藏所有辅助内容。预览只在动作结束或数值提交后编码 PNG，不逐帧截图。截图或贴图失败显示预览错误，不替换原始数据，也不将无贴图占位截图当成生成输入；基础校验通过的姿势仍可应用，交给服务端渲染。

历史记录覆盖完整场景编辑动作，包括人物变换与输出机位，最多保留 30 步，仅保存在弹窗内存。应用才保存，取消和关闭弹窗丢弃未应用编辑；原始候选始终不变。

## 持久化与生图

SceneDraft 新增 poseEdit，包含 sourcePoseId、searchRevision、runtimeRevision 和完整 scene。只保留当前候选编辑；切换候选、修改描述或重新检索立即清空。关闭姿势开关保留编辑，恢复开关可以继续使用；普通模式不提交 pose。

应用时按原子写锁核对候选及检索版本，拒绝迟到编辑覆盖新结果。普通草稿保存保留同候选的新编辑，不可把旧文本编辑携带的旧 poseEdit 写回。刷新恢复已应用编辑；恢复检索姿势清空独立编辑。

生成统一选择已应用 scene 或原候选 matches[i].pose 的完整 JSON，写入既有 poseSelection.pose，保留候选来源标识与描述。提交前复制、冻结到任务快照；Spring Boot 将整个姿势对象序列化为 multipart 的 pose 文本字段，不上传预览 PNG，不提交检索响应包装、pose_id 或文件路径，也不更改 image1/image2 编号或取消协议。服务端渲染失败展示错误并保留草稿、候选及编辑结果供修改或重试。完整姿势仍不进入后续模型上下文。

独立生图页复用同一编辑弹窗与完整 JSON 校验，编辑来源与查询版本在页面内核对。只有应用才更新本地姿势状态，关闭开关保留编辑；普通模式不提交姿势。独立页不写 SceneDraft 到数据库、不生成虚假剧情计划，刷新或离开清空临时编辑。

姿态编辑最初迁移为数据库 v12→v13，备份 v14→v15。只给旧编辑草稿及 computed 内嵌草稿增加 poseEdit=null，不能重跑清空候选的旧迁移。旧候选、选择、提交和原件不变。备份校验编辑来源、检索版本与姿势 JSON 基本结构，容量统计按实际 JSON 自动计入。

## 验收边界

单元测试覆盖场景写回、观察与输出相机分离、历史、候选绑定、保存竞争、切换清除、普通模式、生成冻结和备份往返；迁移测试验证 v12 升级失败原子回滚以及 computed 草稿保留。

浏览器使用真实本地 WebGL、真实资源和 Worker，覆盖站立、拳击、坐姿、跳跃、横竖画幅、不同体型多人物、实际 IK 拖动、数值编辑和撤销重做。图片输出必须包含人体、指定尺寸与白色边角，不接受仅检查请求成功的替代验证。

前端固定资源版本，但外部生图服务未提供资源摘要且仍有独立装配入口；本次不承诺硬件 WebGL 与 SwiftShader 逐像素一致。真实生图服务仍需人工核对外观、姿态和构图，统一两端装配入口及版本校验作为后续工作。
