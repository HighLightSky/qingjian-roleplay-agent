# 图片输入与模型选图实现

图片闭环已与自动剧情、记忆和目标整理接通，详见 [08-消息执行状态与自动整理](./08-消息执行状态与自动整理.md)。原图长期保存在浏览器 IndexedDB，Spring Boot 不保存文件，不引入图片服务器或自动压缩。

> 当前角色文字资料已统一为 name / identity / description；备份仅接受 v3，不兼容旧数据。角色“形象照片”尚未实现，后续参考策略见 [07-角色形象照片与上下文管理](./07-角色形象照片与上下文管理.md)。以下流程描述已实现的聊天图片能力。

## 输入与触发

用户输入可以是文字、图片或图文组合，没有图片模式开关。首次发送图片直接调用正文模型；发送前会话已经有图片消息时，每轮先调用选图模型，包括纯文字轮次。未发送的草稿、设置图库和其他会话中的图片不触发选图。

每轮流程：

1. 等待本会话待处理视觉整理完成，读取发送前的完整图片消息和当前文字上下文。
2. 有历史图片时请求 `/api/context/inspect`。只提交图片目录、来源、观察与使用记录，不传 Base64。
3. 选图模型通过语义选择零张或多张历史图。业务代码只校验 ID、结构、顺序与预算，不使用关键词、字符硬匹配或正则推断相关性。
4. 前端读取本轮新图与选中历史图的原始 Blob，合并去重后随 `/api/chat` 发送。
5. 正文完成后原子保存消息、使用记录和待整理任务，再调用 `/api/state/update`。
6. 统一整理模型实际看图，同时返回视觉观察和剧情、记忆、目标变更；前端校验版本并原子保存。失败保留已完成正文，刷新或下一次发送时重试。

选图目录来自本会话全部用户图片消息，不受界面分页和文字摘要游标限制。`seq/imageIndex/uploadIndex` 保留来源和全会话上传顺序。目录超过规划文字预算时顺序分批，由模型选择候选后再统一决策；候选合并仍无法容纳时明确失败，不静默丢图。

## 接口和协议

| 接口 | 响应 |
| --- | --- |
| `GET /api/capabilities` | `visionSupported/mimeTypes/maxImages/maxImageBytes/maxPixels/maxRequestBytes` |
| `POST /api/context/inspect` | `status/selectedHistoricalImages/candidateAssetIds/message/contextFingerprint` |
| `POST /api/chat` | 既有 `delta/done/error` SSE |
| `POST /api/state/update` | `visualObservations` 及剧情、记忆、目标变更 |

聊天请求携带角色、领域快照、较早原文、历史和交互设置，扩展如下：

```ts
input: {
  text: string;
  parts?: Array<
    { type: "text"; text: string } |
    { type: "image"; assetId: string }
  >;
};
visual?: {
  sessionId: string;
  assetCatalog: CatalogAsset[];
  plan: ImagePlan | null;
  imagePayloads: Array<{ assetId: string; sha256: string; dataUrl: string }>;
};
```

历史消息均有稳定 `id`，图片引用通过 `parts` 发送。本轮新图不进入历史目录；纯文字输入只传 `text`，不再发送旧的 `input.image` 占位字段。

选图计划的指纹覆盖本轮输入、角色、记忆、剧情与目标、较早原文、历史、会话图片目录及观察版本，排除计划自身和补传字节。正文请求重新计算指纹、校验来源和实际字节。首版不维护服务器缓存或持久会话。

选图响应中 `ready` 可以选零张。`ambiguous` 返回候选和澄清文案；`over_limit` 明确暂停。结构或 ID 无效最多纠正一次，不启动正文。历史图保留原消息位置；来源已在较早原文范围时作为明确标注的历史参考附加。

视觉观察只是有损事实记录，不能替代原图，也不能把故事创作当成图中事实。记忆和目标由统一整理器有选择地更新，视觉记录独立保存，不把图片描述直接复制成长期记忆。

## 本地存储与界面

IndexedDB 当前为 v3，包含 `assets/visualObservations/imageUsages/stateTasks/operations/goals`；消息和草稿保存图片引用。资产按 SHA-256 去重，各会话引用与观察独立。原图使用 Blob 存储，缩略图单独生成，Object URL 随挂载创建、卸载释放，不持久化。

输入框只有图片图标，以及有附件时出现的缩略图、移除和必要状态。支持选择、粘贴和拖入；准备失败或未完成时禁止发送。设置中的图片区域分页显示全部数据库资产，可查看原图、尺寸、大小和来源，不提供单独删除或下载按钮。

删除会话或移除草稿附件只清理不再被任何消息、草稿、观察、使用记录、待处理任务引用的原图。重试最近失败的回复复用原用户消息，不再次追加输入。

完整备份当前为 v3，每张原图只保存一份 Base64，包含视觉数据和待处理任务；仅接受 v3，拒绝 v1/v2 备份。导入先验证格式、哈希、像素、来源和引用，再在事务中替换；缩略图重建。导出和导入上限均为 50 MiB，超限明确报错，不省略图片。

## 配置与限制

默认启用当前部署的视觉能力；更换为不支持视觉的模型时通过部署环境变量 `ROLEPLAY_VISION_SUPPORTED=false` 禁用。此配置属于后端能力声明，不是用户界面的开关。

```yaml
roleplay:
  vision:
    supported: ${ROLEPLAY_VISION_SUPPORTED:true}
    max-images: 4
    max-image-bytes: 10485760
    max-pixels: 20000000
    planning-input-chars: 48000
```

首版只支持静态 JPEG、PNG。本轮与历史图共用每次最多 4 张的限制；原图不自动缩小。代理和后端限制请求体为 64 MiB。规划字符预算只是资源保护，不宣称是精确 token 计数。

当前内网模型使用仓库 `cert/server.crt` 的自签名证书。后端 JVM 需信任该证书；验证环境可将证书导入临时 truststore，再通过 `javax.net.ssl.trustStore` 指定。不要关闭 TLS 校验。

## 验证

- 前端单元测试覆盖首次直传、每轮选图和零选择、旧图跨摘要保留、会话隔离、字节哈希、备份、取消、整理失败恢复与消息重试。
- 后端测试覆盖多模态组装、真实图片解码、指纹失效、目录分批、非法 ID 纠正、歧义和视觉观察来源。
- Playwright 在桌面与移动端覆盖图片草稿刷新恢复、纯图片发送、后续纯文字选图、零选图和设置图库。
- 真实模型验收需使用测试地图检查首次看图、观察提取，以及后续追问时的历史原图重读；模型识别本身仍可能出错，不以单次回答代表全部视觉能力。
