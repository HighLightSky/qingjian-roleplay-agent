# 上下文预算与自动压缩

当前实现只展示下一次正文输入占比，以及单次正文调用的输入、输出和总 token；不维护累计用量表。

## 配置与计数

窗口由 `roleplay.context.context-window-tokens` 配置，默认 193024；环境变量为 `CONTEXT_WINDOW_TOKENS`。部署窗口变更后同步修改配置，不以模型训练窗口覆盖部署值。`max-tokens` 是正文最大输出预留，默认 8192。

`ContextProperties` 集中配置触发线 0.70、目标线 0.50、最近保留 10 轮、安全余量 1024、摘要批次输入 32768、最大输出 8192、摘要上限 4096，以及单次最多 8 批。配置关系启动时校验。

`LlmRequestMapper` 为正式请求和模板计数序列化相同消息。`LlamaTokenCounter` 使用同一服务根路径下的 `/apply-template` 和 `/tokenize`，不是 `/v1/tokenize`。文字聊天模板包含生成前缀。图片字节不进入文本 tokenizer；视觉部分按尺寸估算，整体精度为 `estimated`。当前估算参数为 32px 网格、至少 9 格、1.10 倍及每张 64 token 余量，均在同一配置处定义，不代表精确的视觉 processor。

```text
占比 = 本次输入 token / 配置窗口
软触发 = 占比 >= 0.70
硬条件 = 输入 + 最大输出预留 + 安全余量 <= 配置窗口
```

正文、选图、状态整理和压缩各自检查实际输入及输出预留。输入材料的 2000 条历史、2000000 字符保护与 token 预算分别执行；原有图片体积、像素、数量及 64 MiB 请求限制继续生效。

## 接口与类型

`ChatApiRequest` 使用 `summary: {text, throughSeq, version}` 及结构化 `history`，删除 `earlierHistory`。无摘要时三个字段为 `"" / 0 / 0`。每条历史有 `id / seq / role / text / status / checkpointVersion / parts`，仅发送摘要覆盖终点之后的原文。中断回复明确标记未完成，操作和 usage 不进入故事历史。

- `GET /api/capabilities`：增加窗口、输出预留、安全余量、压缩阈值、保留轮数和最大批次。
- `POST /api/context/budget`：`{context, mode, images}`，mode 为 `preview / required / final`，images 为本轮新图的 `{assetId,width,height}`。允许空草稿。preview 为剩余槽位选择估算最大的历史候选图，required 只计算本轮必需图，final 使用已选历史图；不调用生成模型。
- `POST /api/context/compact`：`{operationId, context}`，一次处理一批，返回基准领域/记忆/摘要版本、来源区间和 ID、来源指纹、新摘要及文字压缩前后 token。
- `POST /api/chat`：SSE 首事件 `context`，正文 `delta`，最终 `done: {finishReason, usage}`。`context` 已发送后的生成错误通过 SSE error 返回；预检容量超限返回 `CONTEXT_TOO_LARGE`。

`TokenUsage` 为 `{status:"reported",inputTokens,outputTokens,totalTokens}` 或 `{status:"unavailable",inputTokens:null,outputTokens:null,totalTokens:null}`。输出包含什么以 provider 实报为准，缓存输入不重复相加。流式最终 usage 可能在 finish_reason 之后的空 choices 块，读取到 `[DONE]` 才结束；缺少结束标记视为断流。取消时保留已收到正文，未取得最终用量明确为未知。

`ContextBudgetService.prepare / evaluate / requireSendable` 负责统一预算；`ContextCompactionService.validateRequest / selectBatch / compact / validateResult` 负责有界摘要；`CompactionPromptBuilder.build` 约束摘要仅保留既有事实、因果、承诺、未解决线索和视觉来源。

## 压缩与恢复

发送前先恢复状态整理和压缩待办，再检查文字与必需图片预算、选图、检查最终预算。摘要改变后选图指纹失效，重新选图并计数。输入草稿只触发只读预算预览，不触发模型选图或压缩。

一轮为一个 user 及其后至下一个 user 前的角色回复，不假定消息严格交替。达到触发线或硬条件不满足时，压缩最近 10 轮之前的全部未摘要原文。40 轮的例子为：第 1—30 轮进入摘要，第 31—40 轮保留原文；后台批次预算可能把这 30 轮拆成多次调用。

每批材料包括旧摘要、最早的一批完整轮次和已经提交的视觉观察，模型只输出新摘要，不修改剧情、记忆或目标。未观察图片所在的旧消息不能先压缩。摘要保留图片来源，原图、观察和消息不删除。

摘要结构和引用通过校验且重新组装确实减量后，浏览器检查领域、共享记忆、摘要及来源消息、视觉观察版本，在一个事务中替换摘要、完成 operation、删除 task。尚未达到整体目标的中间批次同样可以提交，以便刷新恢复。

处理完较早历史后，低于触发线并满足容量即可发送；仍超限则明确暂停，保留最近 10 轮、当前输入和必需图片，不静默裁剪。达到批次上限时保留已提交中间摘要。

`compactionTasks` 与 operations 保存 pending/running/computed/committed/failed/cancelled/stale 状态。后端返回后先保存 computed，事务提交失败重试该结果；基准改变则重算。每个任务最多两次自动模型尝试，失败步骤可人工重试；取消后的迟到结果不提交。

## 界面与数据升级

输入区左侧图片、菜单与发送/停止按钮均为 32px。发送按钮左侧使用 assistant-ui standalone ContextDisplay Ring，props 只传当前输入占用，重置键含会话和计数指纹；不读取累计量。悬浮、键盘聚焦或手机触摸显示输出预留、安全余量和统计精度。每条正文回复底部展示该次调用 usage。

IndexedDB v5 从 v4 保留全部本地数据升级：新增会话 summary、旧回复未知 usage 和 compactionTasks；冻结的旧上下文从相同会话原消息重建结构化历史。v3 先执行既有剧情/目标迁移，再执行 v5 迁移；任何一步失败整体回滚。v3 之前沿用既有数据重置规则。旧字段只存在于一次性迁移脚本中。

备份 v6 包含摘要、usage 和压缩待办，仅接受本版格式，先检查结构、所属及引用，再原子替换。原图仍完整保存和校验。

## 已验证

本地 HTTP 夹具覆盖模板计数、图片估算、阈值和硬容量、分批保护最近 10 轮、无效摘要及无减量。浏览器存储测试覆盖 computed 提交失败重用、版本冲突、取消迟到结果、原文保留和备份恢复。

真实部署使用 `Qwen3.8-27B`：`/props` 和 slot 返回 193024，普通及流式请求支持 usage。接入后的文字请求预检 684，实报输入 684、输出 147、总计 831。图片仍标估算，不依据少量样本宣称视觉精确。

真实服务的摘要接口也已验证：12 轮课堂测试材料保留最近 10 轮，摘要覆盖前 2 轮（throughSeq=4），重新组装的输入从 10036 降至 8721 token；摘要通过结构和减量校验。40 轮自动触发、保留最后 10 轮和不删除原文的流程在桌面与手机浏览器中通过模拟服务验收。
