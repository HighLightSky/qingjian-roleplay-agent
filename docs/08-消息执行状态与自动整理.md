# 消息执行状态与自动整理

> `backend-dispatch` 已替换下文的旧调用与迁移策略，当前行为以 [后端编排与缓存](./11-后端编排与缓存.md) 为准。本页保留为设计历史。

图片资产现统一为浏览器全局递增的 `img1`、`img2`；角色照片、选图、视觉整理与摘要共用同一编号。数据库一次性迁移与旧备份转换见 [10-图片短编号与历史迁移](./10-图片短编号与历史迁移.md)。

本次实现消息过程展示与自动维护剧情、记忆、目标，视觉观察合并进同一次整理调用。状态整理实现以本文为准；上下文计数、正文用量与自动压缩已接入，详见 [09-上下文预算与自动压缩](./09-上下文预算与自动压缩.md)。自动演绎仍是后续设计。

## 调用流程

浏览器保存用户输入和待回复消息，先恢复该会话的待整理任务，再按需选图，流式生成正文。非空且 `finishReason=stop` 的正文和整理任务在同一 IndexedDB 事务登记，然后调用 `/api/state/update`。纯文字轮次同样检查。

- 无图片历史：正文 → 统一整理，通常两次模型调用。
- 有图片历史：选图 → 正文 → 统一整理，通常三次模型调用；选图分批或纠正可能增加调用。
- 首次新图直接随正文发送；统一整理再次实际读取本轮使用的原图。
- 选图和整理为 JSON 请求，正文仍使用 `delta/done/error` SSE。界面展示请求与本地保存状态，不展示不存在的后端内部进度或百分比。

## 请求与领域数据

`/api/chat`、`/api/context/inspect` 共用上下文：

```ts
{
  operationId,
  character,
  state: {
    sessionId, characterId, sessionVersion, memoryVersion,
    processedThroughSeq, story, storySources, memories, goals
  },
  summary, history, input, interactionSettings, visual
}
```

所有历史消息均有稳定 ID、序号、状态和来源版本。正文传入历史摘要及未摘要的结构化原文，达到配置窗口的 70% 时压缩较早轮次，保留最近 10 轮原文。完整消息与原图继续留在本地。

`story` 包含地点、故事时间、角色状态（`characterState`）、我的状态（`userState`）、在场人物、关系、物品和未解决线索。剧情只记录当前宏观状态，不回顾历史经过。地点与故事时间通常各不超过30字；双方状态各用一句话、通常不超过80字概括重要穿着、主要情绪与身体情况，未知内容不补全，用户情绪以其明确表达为准。列表每项通常不超过60字，只保留当前在场人物、重要关系、影响后续行动的关键物品和仍待解决的重要问题，不机械列举无关随身用品。有新依据时合并重复项、移除已过时条目，更新返回完整当前列表。

每个字段的 `storySources` 记录人工/自动来源、修改时间与消息引用。记忆包含内容、会话/角色范围、事实类别、有效状态、版本和来源。

新增自动记忆按持续价值选择范围：长期偏好（含稳定称呼）、重要共同经历、持续关系和双方已明确达成但尚未履行的约定进入角色共享记忆；当前地点、穿着、临时情绪和临时物品状态只更新当前会话剧情，不重复创建记忆。只有持续有用但明确仅适用于本会话的信息才创建会话记忆，一次性的行动提议不作为共享约定。该规则用于后续整理，不迁移或重新整理历史会话，已有记忆范围仍由用户手动调整。

目标保留描述和状态，详情只有 `currentFocus`（当前关注点）与 `progressSummary`（完成过程）两项。描述通常不超过40字，只说明要达成的结果；当前关注点通常一句话、不超过60字，只写最关键的关注点或阻碍。完成过程用1—3句概括从目标开始以来的关键进展、决定性线索或转折和当前结果，通常60—120字，提示词要求最多180字，信息少时更短。每次更新结合旧摘要与新依据重新提炼，保留仍重要的早期因果与未解决问题，把中间步骤合并为阶段结果，不逐轮追加行动、对话或尝试，不将计划视为已完成。没有关键进展、关注点或状态变化时不改写；普通动作或一次性互动不单独创建目标。不再使用线索、阶段和阻碍三个字段。

整理以支持后续剧情连贯为标准，只保留会改变人物关系、行动条件、目标判断或后续因果的重要细节，省略逐句对话、动作顺序、语气神态和感官描写。剧情与目标有实质变化时合并重写，已有长文也按相同粒度压缩，不因轮次增加而不断扩写，不为润色或补无关细节而更新。同一事实按用途归入对应字段，不在剧情、记忆和目标中重复铺陈；变更依据 `reason` 通常一句话、不超过30字，不复述新旧全文。上述篇幅要求属于模型提示词约束，字段校验仍沿用现有字符上限；2000字符等资源上限不是生成目标。

正文与选图只读取当前会话的剧情、目标，以及当前会话和角色共享记忆。失效记忆不注入正文；人工删除记录仍提供给整理器，防止从相同来源重建。

统一整理请求：

```ts
{
  operationId, context,
  fromExclusiveSeq, throughSeq,
  messages: [{ id, seq, role, text, status: "complete", createdAt }]
}
```

响应包含操作、基准版本和区间，以及 `visualObservations/storyChanges/memoryChanges/goalChanges` 四个数组。领域变化只允许指定字段的 create/update，包含目标 ID、预期版本、前后值、中文依据和来源。新增 ID、视觉来源与视觉版本由后端生成。没有变化时返回空数组，仅推进已检查游标。

整理模型材料中的 `actualImageAssetIds` 直接取自本次已校验的原图载荷，每张图的内容块同时标注对应 ID。返回模板按实际载荷生成，预填每项观察的真实 `assetId`，模型填写对应的观察内容；来源与版本由服务端生成。每张图恰好返回一项观察；同图兼作角色照片与聊天附件时仍只返回一项。模型结果的结构或引用校验失败后，服务端在保留相同材料和原图的对话中追加失败的 assistant 结果及具体纠正要求，纠正一次；仍无效时明确失败，不猜测 ID 或放行错误观察。连接失败、输出截断和响应体超限不触发这次结果纠正。

服务端校验资源限制、会话所属、版本及消息/图片引用。只允许完整消息成为新变更的来源；未完成的 assistant 正文排除，对应用户输入可以在后续成功轮次检查。陈述、推测、计划与既定事实分开，不替用户承诺或创造事件。

人工编辑不锁定数据，但自动修改人工内容必须引用编辑之后的新消息。该时序同时在提示词和服务端校验；旧结果与当前基准版本冲突时不能提交。

## 操作记录与界面

`operations` 与故事消息分开持久化。运行时按正文锚点插入虚拟 assistant 过程消息，通过现有 Tool UI 展示，标记 `origin: orchestrator`。操作不占故事序号，不进入模型上下文和正文复制。

状态为 pending/running/computed/committed/failed/cancelled/stale。computed 表示后端结果已返回，只有浏览器事务提交成功才显示“已更新”。选图可展开缩略图、来源和用途；整理可展开视觉事实、各类变化前后值和依据；无变化同样有可查看的检查范围。

顶部只保留“剧情与记忆”人工入口，内含剧情、记忆和目标页签。界面使用留白、分隔线和文字层级，目标状态以标题旁的小标签显示。剧情人工修改的字段在名称右上角打星号，自动字段不显示维护标签。

消息引用默认折叠，展开后显示“消息1：开头文字…”并可跳转；预览按可见字符截取，换行归一为空格，已删除消息明确标记。引用适用于剧情、记忆、目标和执行结果。支持键盘展开；手机端跳转关闭面板后定位原消息。

支持编辑、添加、删除、范围调整及目标状态维护，不提供日常手动整理。失败操作提供单独重试；旧轮次选图不允许误触发最近一轮的重试。

模型调用失败与超时的 JSON 响应、SSE `error` 事件在 `message` 中返回异常类型、错误消息和底层原因链，前端直接展示并保存到对应消息或操作记录，便于区分模型输出校验失败、上游 HTTP 错误和连接异常。

## 事务、恢复与版本

正文终态和待办任务原子登记；状态结果在同一事务完成基准版本校验、领域写入、游标推进、操作完成和任务删除。无变化不增加领域版本或更新时间。

服务端返回后先保存 computed 结果。提交失败重试该结果，不重复调用模型；如果基准已变化则重算。每项任务最多两次自动整理请求，每次请求内的无效模型结果最多纠正一次；达到请求次数上限后由失败步骤的重试恢复，不阻止查看已完成正文。版本冲突可在剩余次数内立即重算。

切换会话、停止或刷新不会将后台整理失败改写为正文失败。取消后的迟到结果不提交。刷新恢复执行中操作的终态，保留待办；下次生成前先补做依赖任务。沿用单写入标签页和串行写队列。

## 数据与本期限制

IndexedDB 当前为 v7，新增摘要、正文用量和压缩待办；从 v3—v6 升级保留全部数据，并转换冻结的旧请求。从 v3 升级时在单个升级事务中一次性转换：旧目标的线索、阶段（保留状态）与阻碍合并为完成过程文字，新增双方状态初始化为空字符串；同步转换待办中的冻结快照及操作结果的目标前后值。保留原消息、版本、来源和待办次数，失败全部回滚，正常启动不重复迁移。迁移保留已有文字，不调用模型、不静默截断；若旧内容合并后超过当前单字段上限，需在人工入口缩短后继续请求。

旧类型仅定义于升级脚本中；应用类型、接口、提示词和渲染只使用新结构，没有运行时旧字段回退。从 v3 之前的结构升级仍沿用此前已确认的数据重置规则。

备份升至 v8，仅接受本版格式，包含领域状态、操作结果和待办。导入先校验结构、所属和引用，再事务替换；图片原件、大小、像素和哈希校验继续保留。

资源限制集中于后端 `ContextLimits`，未摘要材料最多 2,000 条消息、2,000,000 字符。token 预算独立检查；纯文本使用部署模板和 tokenizer，有图请求标为估算。原图限制沿用部署视觉配置。

角色照片、联合视觉来源及 v6 数据库升级详见 [07-角色形象照片与上下文管理](./07-角色形象照片与上下文管理.md)。
