# 图片短编号与历史迁移

> `backend-dispatch` 已替换下文的旧调用与迁移策略，当前行为以 [后端编排与缓存](./11-后端编排与缓存.md) 为准。本页保留为设计历史。

角色照片、聊天附件、选图、正文原图、状态整理、上下文摘要、图库和备份统一使用 `img1`、`img2` 等图片资产 ID。编号在浏览器数据库内全局唯一，与消息、角色、会话及附件准备期间的临时 ID 无关。接口字段名与结构不变。

## 分配与生命周期

`frontend/lib/images/ids.ts` 集中定义编号格式、计数器键及分配方法。`settings` 保存 `{key:"imageAssetSequence",value:"0"}`，值为最后分配的编号。新数据库初始化为 0。

`prepareImage()` 与 `prepareCharacterPhoto()` 共用 `getOrCreateImageAsset()`。文件检查、哈希及缩略图准备在事务外完成；事务内先按 SHA-256 去重，仅新资产调用 `allocateImageId(tx)`。计数器、资产和草稿引用在同一读写事务提交，失败一起回滚。事务序列化保证并发分配不重号，不依赖内存计数器或页面写队列。

相同文件复用 ID，删除不回收编号。角色照片与各会话共用资产编号，但观察和上传来源仍属于各自会话。`uploadIndex` 继续表示会话内上传顺序，不能从 `imgN` 推断“第几张上传图”。图库按编号数值排序后分页。

计数器缺失、损坏或超过安全整数范围时明确失败，不扫描资产补值。只有“清空全部数据”才将计数器归零；恢复备份在覆盖事务内取本地原计数器和备份计数器的最大值。

## 模型协议

图片 ID 必须符合 `img` 加无前导零的正整数格式，旧 UUID、`img0`、`img01` 等被正式入口拒绝。前端共用 `assertImageId()`；后端通过 `ImageIds.requireValid()` 在角色照片、目录与新图入口校验。其余引用通过集合归属与一致性检查验证。

选图模型原样复制目录 ID，状态整理的清单和返回模板按实际载荷预填短 ID。角色参考、历史原图、本轮新图和已进入摘要的历史参考图均有明确 ID 标注。模型返回的非法引用、重复或缺失观察继续被拒绝，原有一次结果纠正保留。

摘要通过 `ImageIds.referencedIds()` 提取完整编号后检查必需引用，不使用子串包含关系，因此 `img10`、`img100` 不能代替 `img1`。中文与标点可以直接相邻，英文标识符中的子串不算引用。

## IndexedDB v7 升级

`database()` 仅在升级事务调用 `migrateV7(tx)`。v3—v5 先执行原有领域、摘要与联合视觉来源升级，再执行图片编号迁移；v6 直接执行本次迁移。正常运行不读取旧格式。v3 之前沿用原有数据重置规则。

迁移按 `createdAt` 时间升序、旧 ID 字典序分配 `img1` 至 `imgN`；旧新映射仅存在于迁移内存，不持久化。共用的纯数据转换函数 `migrateImageIds()` 更新：

- 资产主键；当前角色、会话快照、角色草稿中的照片引用。
- 消息与附件草稿的图片内容块。
- 观察、使用记录的资产引用及复合主键。
- 整理与压缩待办的冻结角色、输入、历史、目录、观察、选中集、候选集及载荷引用。
- 选图、整理与压缩操作结果中的图片引用。
- 会话、冻结上下文及压缩结果摘要中的完整旧图片 ID。

不对整个 JSON 做字符串替换；用户原始消息、角色自由描述、可辨文字及其他图片观察内容保持原样。缺少必需原图或复合主键不一致时，错误指出具体表、记录和图片 ID。

所有表在同一升级事务读取、转换、重写。先清除旧键及唯一哈希索引再写入，计数器设为 N。原图 Blob、缩略图、SHA-256、来源、消息序号、领域/观察版本、时间戳、任务次数与已计算结果保留。迁移失败整体回滚，数据库仍为旧版本，可修复后重试；再次打开新版不重复迁移。

历史指纹保留为原调用审计值，不伪造新指纹。新的正文请求重新选图并计算指纹；状态待办使用迁移后的原选中集，已计算结果仍按既有版本校验提交，不重新调用模型。

## 备份 v8 与独立转换

正式导入仅接受 v8。计数器随 `settings` 导出，导入校验其格式及是否覆盖全部资产编号；原图字节、像素、哈希、来源与引用校验继续保留。

在 `frontend` 运行：

```bash
npm run migrate:backup -- old-v7.json new-v8.json
```

独立工具仅接受 v7，检查旧结构及重复键后调用与数据库相同的转换函数，最后通过正式 v8 校验再输出。原图 Base64 不重新编码；输入和已有输出文件均不覆盖。应用导入入口不调用此工具，也不接受旧版本。新旧前后端需同步发布。

## 验证

单元测试覆盖跨角色/会话分配、同文件复用、并发、事务失败回滚、删除与清空、计数器损坏、备份最大值策略、完整旧数据迁移、旧备份命令及已计算结果直接提交。后端覆盖非法编号入口和完整摘要引用；浏览器覆盖照片/聊天图片链路及图库数值排序分页。
